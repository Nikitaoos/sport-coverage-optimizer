# sport-coverage-optimizer

Оптимизационная модель покрытия спортивного объекта устройствами видеорегистрации.

**Курсовой проект**, КубГУ, кафедра информационных технологий, 2026.

## Описание

Программный комплекс решает двухэтапную задачу:

1. **Стационарные камеры.** Размещение формализовано как задача целочисленного
   линейного программирования (максимизация числа покрытых точек наблюдения при
   бюджетном ограничении на число камер). При равенстве покрытия предпочтение
   отдаётся более дешёвой конфигурации.
2. **Подсистема БПЛА.** Для точек, не покрытых камерами, строятся маршруты
   облёта при заданном бюджете флота `K_d` и ограничении на длину маршрута
   `R_max`. Маршрут наращивается по критерию максимального прироста
   наблюдаемости на единицу длины и улучшается локальным поиском (2-opt,
   Or-opt, замена точки) с лексикографическим критерием: сначала
   наблюдаемость, затем длина. Точка
   считается наблюдаемой, если расстояние от неё до ломаной маршрута не
   превышает радиуса полосы наблюдения `r_obs`.
3. **Определение состава флота.** В режиме `--target-coverage` подбирается
   минимальное число аппаратов, обеспечивающее заданный уровень покрытия.

Оба бюджета (`K` и `K_d`) и ограничение `R_max` являются **связывающими**:
при недостаточных ресурсах часть точек остаётся непокрытой, и совокупное
покрытие оказывается строго меньше 100 %. Покрытие БПЛА вычисляется
геометрически, а не постулируется.

Конфигурации сравниваются по совокупной стоимости владения (TCO) методом
взвешенной суммы нормированных критериев.

```
sport-coverage-optimizer/
```

## Установка

```bash
pip install -r requirements.txt
```

Обязательная зависимость только одна — `numpy`. При отсутствии `pulp` и
`scikit-learn` используются встроенные реализации (жадное покрытие множества и
Lloyd's algorithm), результат при этом может быть чуть хуже оптимального.

## Запуск

```bash
python main.py --input data/stadium_example.xml --budget 12 --drones 4
```

### Параметры

| Параметр | Описание | По умолчанию |
|---|---|---|
| `--input` | Путь к XML-описанию объекта | `data/stadium_example.xml` |
| `--budget` | Бюджет стационарных камер `K`, шт. | `12` |
| `--drones` | Бюджет флота БПЛА `K_d`, шт. | из XML (`max_units`) |
| `--drone-range` | Максимальная длина маршрута `R_max`, м | из XML (`range_m`) |
| `--obs-radius` | Радиус полосы наблюдения `r_obs`, м | из XML (`obs_radius_m`) |
| `--no-drones` | Отключить подсистему БПЛА | выкл. |
| `--grid-step` | Шаг сетки точек наблюдения `δ`, м | `5` |
| `--target-coverage` | Целевое покрытие, %; включает подбор минимального флота | не задано |
| `--w-coverage` | Вес критерия покрытия в Score | `0.7` |
| `--output` | Путь к выходному XML-отчёту | `output_config.xml` |

## Формат описания объекта

```xml
<venue name="..." type="stadium" capacity="5000">
  <sectors>
    <sector id="S1" name="..." x="20" y="65" width="60" height="12" priority="1"/>
  </sectors>
  <camera_positions>
    <position id="C1" x="3" y="77" azimuth="315" angle_h="80" range_m="35" cost="80000"/>
  </camera_positions>
  <forbidden_zones>
    <zone id="FZ1" name="..." x="20" y="15" width="60" height="50"/>
  </forbidden_zones>
  <drone_params range_m="50" obs_radius_m="12" max_units="4" cost_per_unit="15000"/>
</venue>
```

Система координат: метры, начало — левый нижний угол объекта.
Азимут: 0° = север (+Y), отсчёт по часовой стрелке.

## Ограничения модели

- Геометрия двумерная: перекрытие видимости навесами, конструкциями трибун и
  перемещающимися зрителями не учитывается, поэтому оценки покрытия являются
  верхней границей.
- Наблюдение БПЛА считается мгновенным по всей длине маршрута; периодичность
  повторного облёта, время смены аккумуляторов и погодные ограничения в модель
  не входят.
- Все точки сетки равнозначны: приоритеты зон загружаются из XML
  (`SpatialModel.point_priority`), но в целевой функции пока не используются.
- Маршруты БПЛА строятся эвристикой (K-means + жадное наращивание + локальный
  поиск) и не являются оптимальным решением задачи об ориентировании.
- При радиусе полосы наблюдения, сопоставимом с размером остаточного кластера,
  маршрут вырождается в точку зависания; в этом режиме корректнее включать
  позиции зависания в множество кандидатных позиций задачи размещения.

## Стек технологий

- Python 3.9+
- numpy — матричные операции, векторизованная геометрия
- xml.etree.ElementTree — парсинг описания объекта и генерация отчёта
- PuLP / CBC — точный решатель ЦЛП (опционально)
- scikit-learn — K-means (опционально)
